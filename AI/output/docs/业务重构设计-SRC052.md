# 业务主线重构设计

来源：SRC-052，用户对当前包按 HTTP、mail、file、model 等技术名词展开的结构提出纠正，并要求参考 itineary 的 `@AiService`、RAG 与 start 装配。

## 结论

一期产品只有三条一级业务主线：认证、知识库、对话。旅行规划、长期记忆、同步推送和后台恢复是对话的内部能力；邮件、文件、安全、模型、向量库是业务所使用的技术端口，不能再作为与业务并列的一级包。

`util`只承载无状态、无配置、无 IO、无业务语义的纯函数。文件解析、SMTP 投递、密码哈希、模型调用、Milvus 访问均有失败、配置、审计或资源生命周期，因此分别留在所属业务的 output 端口，不能降级为 util。

## 目标结构

```text
adaptor
  auth/input/{controller/AuthController,assembler/AuthInputAssembler}
  auth/output/{email,security}
  knowledge/input/{controller/KnowledgeController,assembler/KnowledgeInputAssembler}
  knowledge/output/{embedding,file,vector}
  chat/input/{controller,assembler}
  chat/output/{agent,memory,travel}
  web/support                         # 跨业务 HTTP 过滤、Cookie、错误与协议响应

application
  auth/{email,security,command,result,service,usecase}
  knowledge/{document,vector,command,result,service,usecase,job,retrieval}
  chat/{context,memory,planning,sync,command,result,service,usecase}
  support / tx                        # 跨业务JSON和事务协作，不放业务路由

start/config
  AiConfiguration                     # 聊天、流式聊天与知识嵌入命名模型
```

## Agent 与 RAG

对话的旅行回答、意图解析、记忆摘要和显式事实提取分别使用用途明确的端口；对应 LangChain4j 接口使用 `@AiService(wiringMode = EXPLICIT)`。start 提供命名 `ChatModel`、`StreamingChatModel` 与知识库 `EmbeddingModel`，适配器不再为每个请求创建 SDK Client。回答端口以 `Flux<String>` 保留增量文本，适配器累积完整草稿并执行长度与租约回调。

RAG 的嵌入端口归知识库 `vector.embedding`，文档写入、删除和状态账本仍由知识库业务维护；Milvus 仅做向量检索。当前不直接采用通用 `ContentRetriever`：检索结果必须逐条以用户、文档状态、删除代次、索引代次和正文哈希进行 MySQL 权威校验，自动检索器无法独立表达这些约束。后续若引入 `ContentRetriever`，只能包装在同等业务治理之后。

## 实施结果

- `application/model` 与 `adaptor/model` 已删除；内部结果拆为 `model.chat.ChatModelDO` 与 `model.knowledge.EmbeddingDO`。
- 意图、回答、摘要、事实提取和知识嵌入各自拥有业务语义端口，不再通过 `ModelCommand.action` 动态选择。
- `adaptor` 一级目录仅保留 `auth`、`chat`、`knowledge`、`web` 和层内异常；协议名 `http` 不再作为一级业务目录。
- `AiConfiguration` 显式装配普通聊天、流式聊天及知识嵌入模型；无密钥时使用禁用模型，离线 Spring 装配通过。
- 旅行历史由 assembler 按角色显式投影，不再依赖 Java 对象默认 `toString()` 拼接提示。

## 迁移约束

1. 先建立业务端口和 start 装配，再迁移调用方，避免出现无实现的接口或重复模型调用。
2. 每次迁移后运行完整 Maven 测试、依赖边界与业务质量门禁。
3. `workflow`仅保留有状态图语义的旅行规划图；普通邮件、文件、索引、同步和动作分派不使用该名称。
4. 迁移不得把技术异常穿透业务或 HTTP 边界，也不得改变现有用户、会话、幂等、删除代次和同步序列不变量。
