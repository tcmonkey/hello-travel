## 2. 修订后的完整职责链路

认证HTTP入口：解释允许路由→取得可信设备身份→AuthInputAssembler整体转换→应用认证→维护Cookie→公开响应投影。未知路由在签名设备前拒绝。Controller不创建DomainException，不直接new AuthCommand；认证身份check不继承共享refresh凭据，公开响应不含refreshToken或内部数字ID。

异常创建：协议动作/转换由AdaptorException表达，Bean Validation继续处理请求参数约束；应用流程创建ApplicationException；领域创建DomainException；持久化创建InfrastructureException。下层已分类BaseException通过公共失败契约保留，禁止机械改写为通用不可用。外部公开入口保留完整try-catch；内部受控异常仍服务事务回滚，不在Controller逃逸。

对话/同步：ChatInputAssembler/SyncInputAssembler承接身份和分页默认、请求映射及结果投影；ChatApplicationAssembler/SyncApplicationAssembler承接实体和持久事件的应用视图。SSE使用公开事件转换并持续校验原页面SID，不暴露Application Result作为协议。

认证/文件/模型/向量/安全/邮件/出行：各用途CommandAssembler统一来源字段与预设；OutAdaptor处理真实IO，OutputConverter承接SDK/JSON/内部DO。上传边界先验容量再读字节；IOException仍安全FAILED/500。无账号密码验证的固定保护摘要归安全预设，模型任务提示归专属模型命令转换，不建立全局常量杂物箱。

写入/仓储：TravelWriteApplicationAssembler整体接收Aggregate生成所属Param；DomainWrites协调领域调用与失败；17个PersistenceConverter显式PO↔Aggregate映射；Repository仅控制查询、新增/CAS、版本时间与DAO错误。所有字段使用往返检查核对，包含归属、删除时间、版本和字节数组。

上下文/索引：ModelContextPolicy统一应用预算、压缩输入上限、外部模型输出限额；超预算输入在模型IO前拒绝。ContextApplicationAssembler投影估算预算与实际usage，实际usage缺失保持未知；前端ContextBudget只读服务端预算，没有客户端32768/4096猜测。KnowledgeIndexPolicy统一嵌入模型、1024维和hello_travel_kb_v1_d1024集合，Domain使用EmbeddingProfileValue接受已选策略。Milvus字段与模型输入转换先验证归属/维度/有限值/批量大小，再发生客户端或Schema IO。

删除失效ApiViews反射通用投影与标量view辅助；保留必要领域工厂、配置装配、Schema和协议字面量。不能将“hardcode整改”理解为删除全部常量或禁止领域实体的不可变复制。

## 4. 漏检原因与约束落实

MAP-001/002/003和分层职责约定此前已经存在。我上一轮聚焦编号注释、方法规模和有限领域结构，缺少全项目转换构造位置与异常创建归属清单，并把静态通过当成了更广的人工复核证据。这是执行和审查遗漏，不能归因于用户没有表达、技能没有规则或生成速度快。

规范1.9增加MAP-006/ERR-008以明确可操作边界；QUALITY-MAPPING/QUALITY-ERROR-OWNER自动拒绝有限已知构造模式。实际改动接收完整来源对象及有用途预设方法，而非将长标量串原样搬入assembler。后续迭代必须先复核既有完整链路，再决定复用、替换、重构和删除；静态检查之外仍需核对来源、敏感字段、不变量、失败和事务语义。
