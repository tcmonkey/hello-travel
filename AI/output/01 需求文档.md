# 需求文档

## 1. 背景与现状

用户希望通过本地旅行助手项目，验证 solo 能否支持一人开发完整交付流程，并审阅首版方案和代码质量。目标目录为 `/Users/monkey/Documents/kit/workspace/hello-travel`，由本回合创建。

所有服务部署在本机；用户表示已安装 MySQL、Redis 和 Milvus，尚未核实版本、连通性、账号或运行状态。阿里百炼及高德凭据位于 `~/.zprofile`，本阶段未读取；后续使用时不得将值写入代码、文档、日志或终端输出。

事实来源为 SRC-001 与 SRC-002。SRC-002已明确多业务表、设备内页面登录替换、跨设备消息同步及新登录完整历史恢复。下文标记“建议”的规则属于待确认设计，不能冒充用户已批准。

## 2. 问题陈述

旅行规划信息散落在不同来源，用户希望以连续对话补充目的地、时间、预算和偏好，获得包含交通、天气、景点、酒店、优先级、提醒、规则和售后政策的规划。多对话与多用户之间必须隔离数据与模型记忆；长对话应可控地压缩，并让用户看见上下文占用。

一期只咨询和规划，不完成预订、购票、退款或支付。模型不得把计划或政策咨询描述为已完成的实际交易，也不得编造实时天气、价格、营业状态或退改条款。

## 3. 目标与成功指标

1. 首版生成与需求可追踪的前端、后端、数据库迁移、配置样例和必要测试代码，架构及核心规则有独立方案文档。
2. 设计覆盖正常、空数据、错误、权限、并发和外部服务不可用的行为；单机部署不作为跳过业务建模、认证、隔离、事务和恢复机制的理由。
3. 账号、会话、记忆、知识库的权限边界和数据生命周期可审阅；正式实现时不存在明文密码、提交密钥或仅以前端隐藏实现权限控制。
4. 生成完成≠本地可运行、自测完成、CR完成、独立测试通过或生产就绪；实际运行证据逐项单独记录。

**本次用户指定终点：05 编码开发中的代码生成完成。** 允许为代码质量做编译和必要静态检查，并记录真实结果；不据此代替06开发自测或07代码审查结论。不自行推进独立测试、发布和效果评估。

## 4. 非目标

- 二期门票订单正向流程、取消/退款等逆向流程、支付、对账、实际售后工单与交易执行。
- 本期不加入已登录账号主动修改密码的独立功能（用户表述“后续再更新密码”）；验证码找回/重置属于一期。
- 集群部署、分库分表、分布式可用性承诺、真实生产发布、真实经营效果和压测达标声明。
- 未经确认的全站管理员、跨用户共享知识库、商业地图购买、第三方酒店/票务下单、营销邮件。
- 复制 Codex 的品牌或内部实现；参考其左侧菜单和右侧对话的布局关系。

## 5. 用户角色与场景

- 未登录访客：注册，邮箱密码登录，邮箱验证码登录，密码找回/重置。
- 已登录旅行者：多个会话进行咨询和规划；查看历史与上下文占比；管理自己的知识资料。
- 资料维护者：一期建议与旅行者为同一账号，知识库默认私有。是否共享见 ASM-002。

典型流程：注册并验证邮箱 → 登录 → 新建“景德镇周末旅行”会话 → 补充出行时间/预算 → 获得分日建议、优先级和来源提示 → 询问景区退改政策 → 查看引用 → 刷新后恢复会话 → 删除消息后该内容不再参与后续模型记忆。

## 8. 业务规则与边界

以下为待确认建议；用户明确需求优先。

- BR-001：邮箱为账号标识，规范化规则明确且数据库唯一；注册须邮箱验证。验证码登录默认只用于已注册账号，未知邮箱引导注册，不隐式创建账号。
- BR-002：验证码按邮箱＋用途绑定，短时有效、一次性、限制发送和尝试次数；本地通过可配置邮件适配器发送。缺少SMTP配置时明确不可用，不能在生产逻辑中接受固定验证码或假装发送成功。本回合不发送真实邮件。
- BR-003：设备是同一浏览器配置下可持续识别的设备实例；另一个浏览器/隐私窗口视为独立实例，不声称识别真实物理设备。SRC-002明确设备内替换；物理设备不能仅凭浏览器可靠识别，具体浏览器实例定义在产品方案待确认。
- BR-004：重置密码建议撤销所有设备旧会话；退出仅撤销当前会话。安全策略细节在产品与技术阶段明确。
- BR-005：会话删除及消息删除从可见历史和有效记忆中移除，不将“全部记录”理解为无限期保留已删除个人内容；建议先逻辑删除、明确清理期限并异步删除派生索引，不继续使用已删除正文。
- BR-006：同一会话同时发送请求需序列化或受控拒绝；请求重试必须幂等。生成中的删除需取消或拒绝，具体交互在产品方案确定。
- BR-007：对话历史、短期摘要与长期记忆默认均按用户＋会话隔离；若后续要跨会话个性化，须显式修改需求并说明共享、撤销和删除语义。
- BR-008：知识库默认用户私有；示例资料使用显式导入方式，不向所有用户自动暴露其他账号的上传内容。若需要共享公共知识库，产品阶段明确来源与授权。
- BR-009：上下文比例以实际模型的有效输入预算为分母；包含所有提示输入，扣除预留输出与安全裕量；界面注明“估算”或“实际”及更新时机，不能只按聊天字符数伪装真实token占比。
- BR-010：压缩只改变模型输入视图，不直接覆盖全量对话；来源消息删除后摘要、长期事实和派生索引须失效。无法安全压缩时停止本轮或要求用户缩短，不截掉关键系统约束。
- BR-011：工具和RAG结果属于资料，不是授权指令；模型不得获得数据库任意查询、文件任意读取、邮件任意发送或支付权限。
