# 产品方案

## 1. 方案摘要与原则

一期交付邮箱认证、持久化多对话、实时跨设备同步、旅行咨询与规划、可解释上下文管理、私有知识库和来源引用。用户已明确：一个hello-travel数据库，多业务表；不同设备并行，同设备新页面登录踢旧登录；任何设备新增消息需要同步；新登录恢复完整历史（SRC-002）。

本方案是可审阅的业务基线，新增建议规则尚未批准。登录会话与对话框是两种对象：撤销登录只影响访问资格，不删除对话历史。全量历史与模型输入是两种视图：全部历史可以恢复，不意味着全部历史都发送给模型。

本回合将02产品、03UI及04技术草案一起展示，方便用户同时审阅实时同步和表结构；不将草案生成视为审批或编码完成。本次终点仍为05代码生成。

## 2. 用户角色和核心场景

未登录用户通过邮箱验证码统一登录，首次验证自动创建账号；已设置密码的账号也可使用密码登录，密码通过邮箱验证设置或重置。已登录用户管理本人会话、咨询规划及上传本人知识资料。默认不设管理员、不共享不同用户资料；官方示例以显式导入方式提供。

场景A：手机浏览器和桌面浏览器同时登录，桌面发送“景德镇周末两天”，手机收到用户消息和助手生成状态/回答。

场景B：同一浏览器新页面主动登录，旧页面被踢，停止订阅和提交；新页面读取服务端完整历史，原对话框及记录不受影响。

场景C：手机离线后重新上线，补齐离线期间的修改；补齐游标过期时重新恢复完整历史，不永久漏消息。

## 3. 信息架构

```text
Hello Travel
├─ 对话管理
│  ├─ 新建对话
│  └─ 对话tab列表（选择/重命名/删除/新消息提示）
├─ 知识库管理（右侧切换为上传＋资料列表＋明文详情）
└─ 账号区（当前邮箱/退出）
右侧对话：历史＋引用＋输入区＋本轮上下文侧栏
```

| FLOW-004 tab管理 | 新建→选择→重命名/删除→服务端保存→其他在线设备同步 | 空名、保存失败、删除取消、正在生成时删除的处理见RULE-010 | F008/F009/F010/F011/F028 |

| FLOW-009 断线补齐 | 连接中断→显示重连→按持久游标补齐→状态合并→继续接收 | 游标过期→重新取完整快照；新旧连接重复事件去重；其他设备不强制跳转当前页面 | F011/F014/F028 |

## 5. 功能详细设计

| 功能 | 关联需求 | 前置条件 | 主流程 | 异常与恢复 | 结果 |
|---|---|---|---|---|---|
| 邮箱认证 | F001～007 | 有可用邮件适配器；密码登录需已设置密码 | 登录验证码同时承担首次邮箱验证和既有账号登录；账号支持验证码登录，密码为可选凭据 | 投递受理不等于已送达；缺SMTP明确不可用；重置撤销所有旧登录 | 可撤销的认证态 |
| tab持久化 | F008～011 | 本人有效登录 | 新建默认“新对话”，名称纯文本，侧栏按最近活动排序 | 失败保留原状态；删除当前tab选择邻近tab或空态 | 刷新、新登录不丢tab |
| 消息与生成 | F012～014 | 本人未删除会话，当前无进行中生成 | Enter发送；保留用户输入，回答流式展示并服务端定期保存草稿 | 重试原请求不重复用户消息；失败显示“回答生成失败”，显式重试沿用该输入；停止保留已确认草稿并标记取消 | 有顺序和状态的完整历史 |
| 隔离及记忆 | F015/F016/F018 | 用户＋对话归属验证通过 | 原始历史、近期消息、结构化摘要、显式长期事实分别维护 | 删除使派生记忆代次失效；压缩只改输入视图；不同对话不串记忆 | 有来源的上下文 |
| 上下文占比 | F017 | 已选择会话 | 展示有效输入预算占比、估算、组成、压缩状态；实际值由供应商确实返回后补充 | 切会话不沿用前一会话进度；使用过期/压缩中标签，不编造精确数字 | 用户可理解本轮占用 |
| 旅行咨询 | F019～021 | 当前输入及可用工具/知识 | 按天组织路线、交通时长、优先级、住宿建议、提醒、适用规则和引用 | 远期天气、票价/库存或公开政策不可得时说明未知；不执行预订或售后 | 可追溯的规划建议 |
| 私有知识库 | F022～026 | 本人登录 | TXT/MD/PDF作为一期建议支持类型；列表和明文详情；索引成功后检索 | 建议10MiB文件上限/2MiB提取文本上限；失败可重试；景德镇示例只用已核验来源 | 不影响既有Milvus集合 |
| 应用布局 | F027 | 登录或认证视图 | 左侧两个同级菜单，右侧会话/知识视图，Logo左上，上下文在对话一侧 | 窄屏折叠菜单/上下文；键盘可操作 | 一致清晰的交互 |
| 跨设备同步 | F028 | 同账号不同设备有效登录 | 用户消息提交即同步，生成中的状态/片段也同步，完成以服务端最终消息为准；tab/删除变化一并同步 | 重复去重、版本防覆盖、断线补齐；被踢会话停止订阅，不自动换新会话 | 微信式消息同步的核心体验 |

知识文档删除是管理建议（关联F022/F024生命周期），尚待产品确认；本期不加入资料编辑或跨用户分享。

## 6. 页面与状态

| 状态 | 对话视图 | 知识库视图 | 认证/全局 |
|---|---|---|---|
| 加载 | “正在恢复完整历史”，显示分段进度，输入在所选会话初始恢复完毕前禁用 | 列表骨架；明文加载独立 | 校验原页面登录会话，不隐式接入另一登录 |
| 空数据 | 欢迎提示和新建按钮 | 上传引导 | 统一邮箱登录入口 |
| 进行中 | 用户消息已发送；助手“规划中/检索中/压缩中” | 已接收/解析中/索引中 | 验证码请求“已受理，请留意邮箱” |
| 成功 | 最终消息、引用、预算更新 | READY可检索，明文可读 | 登录恢复全部服务端历史 |
| 部分成功 | 部分工具不可用，保留已核验建议并说明缺项 | 解析成功但索引失败仍不能宣称可检索 | 不把SMTP接收当最终投递成功 |

| 被踢 | 撤销当前订阅和提交能力，页面提示被新登录替换 | 同样禁止受保护操作 | 不删除对话，不自动刷新为新登录 |

## 7. 业务规则与校验

| ID | 规则 | 属性 |
|---|---|---|
| RULE-001 | 单库多业务表，不分库分表；库名hello-travel | 用户已明确 |
| RULE-002 | 不同设备并行；同设备主动新登录原子撤销旧登录 | 用户已明确 |
| RULE-003 | 同一设备定义为同一浏览器配置中的稳定实例；另一个浏览器/隐私窗口独立。不声称识别真实物理设备 | 技术上可实现的建议定义 |
| RULE-004 | 旧页面保存原登录会话标识；即便共享Cookie变更，也不得自动接入新登录；刷新当前有效页不互踢 | 对RULE-002的必要实现语义 |
| RULE-005 | 新登录拉全量tab和完整历史；分页只是传输方式，不以最近N条替代全量。所选会话优先，其他会话后台分段恢复，页面虚拟渲染 | 用户要求＋性能设计建议 |
| RULE-006 | 账号邮箱规范化后唯一；有效登录验证码在签发会话事务中原子创建或读取账号；密码为可选凭据，重置用途可设置首个密码或替换旧密码，并撤销所有旧会话 | 用户已确认的认证规则 |
| RULE-007 | 密码建议12～128字符，不静默截断；验证码5分钟、失败最多5次、每邮箱用途60秒发送间隔，均配置化 | 安全产品建议，待确认；不冒充已测参数 |
| RULE-008 | tab名建议1～120字符；消息大小、会话数量和文件额度有配置上限及提示 | 资源边界建议 |
| RULE-009 | 同一对话最多一个进行中生成；另一设备可看进度，同时发送受控繁忙；不同会话可以并行，但受账号/全局并发预算约束 | 一致性建议 |
| RULE-010 | 生成中消息删除/重命名允许性：重命名可行；删除消息提示先停止；删除整个对话先取消并使运行栅栏失效 | 删除安全建议 |
| RULE-011 | 删除消息/对话从所有设备视图移除；相关短期摘要、长期事实和索引失效。历史在服务端完整持久化不意味着无限期保留删除正文 | 必要需求解释，清理期限待技术方案 |
| RULE-012 | 一期长期记忆也按用户＋对话隔离；只采纳有原用户消息证据的明确偏好/限制/已确认计划，模型猜测不成为事实 | 建议，符合隔离要求 |
| RULE-013 | 知识库默认用户私有，明文仅本人可见；官方示例显式导入，不自动公开用户上传 | 建议待确认 |
| RULE-014 | 上下文比例包含系统提示、工具定义/结果、摘要、近期消息、长期事实和RAG资料，预留输出与安全量；压缩不删历史 | 必要需求解释 |
| RULE-015 | 工具/RAG正文不作为授权指令；实时信息须带来源和时间；未知不能补造 | 安全与真实性建议 |
| RULE-016 | 其他设备在同对话追加消息，非当前对话提示新消息，不抢焦点/切页；正在编辑的本地未发送内容不覆盖 | 同步体验建议 |
| RULE-017 | 文档导入中与失败不可检索，重试绑定新的索引代次；向量命中需验证当前资料归属、状态和版本 | 必要RAG一致性规则 |

## 9. 提示、通知与文案

“此页面的登录已被同设备的新登录替换，请重新登录。”“连接中断，正在补齐消息。”“本轮上下文约使用xx%，为估算值。”“正在压缩较早的对话；原始历史会保留。”“暂无可靠的该日期天气/价格信息，请在出行前核实。”“资料解析完成但索引失败，当前还不能检索。”

不实现站外消息通知、营销邮件或订单通知。本地新消息提示仅表达消息同步；本期不承诺微信的好友、送达/已读回执、跨设备草稿或后台推送能力。

本地后端指标/日志即可，不引入外部分析服务。不编造目标已达标。

## 11. 兼容性与无障碍

目标为当前主流桌面/移动浏览器；键盘可完成登录、导航、新建、发送、展开引用与关闭弹层。Enter/Shift+Enter区分；中文输入法组合状态不触发发送。新消息不打断焦点，虚拟历史提供可读标签，进度带数值/文字，不只用颜色表达。

## 12. 本期范围与后续范围

一期为F001～028和NFR；保留用户指定Spring Boot/LangChain4j/LangGraph4j/RAG/MySQL/Redis/Milvus组合。本次做至05代码生成；06～14保持未执行。

二期订单、支付、退款执行另立需求与授权；资料编辑、共享公共知识库、微信式阅读回执/后台推送/跨设备草稿不属于当前明确范围。
